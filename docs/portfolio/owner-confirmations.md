## 답변과 작업 원칙

아래는 나중에 사용자가 설명해줘야 할 **사실·경험·공개 범위**다. 지금 답변을 모두 요구하거나 포트폴리오 개편 전체를 중단하는 목록이 아니다. 답변 없이도 근거 요약을 사용해 문장 정리와 배치를 진행한다. 단, 각 항목에 적힌 미확인 주장은 답변 전에 확정하지 않는다.

답변은 `항목 ID → 설명 → 기간/대상/산식 → 공개 가능한 범위`로 기록한다. 원본 증빙이 없어도 경험을 설명할 수 있으며, 이때 **사용자 설명 / 당시 추정 / 문서 기록 / 측정 근거 확인**을 구별한다. 단순히 ‘맞다’고 확인한 수치를 독립 측정 결과로 승격하지 않는다. 기억이 없거나 측정하지 않았으면 그대로 답하면 된다.

답변 도착 시 해당 질문 아래에 날짜·요약·근거 수준·허용 문장·남은 질문을 기록하고 근거 요약/증거표/개편 백로그를 함께 갱신한다. 상태는 `미답변 / 일부 답변 / 확인 완료 / 미측정으로 확정 / 공개 제외`로 관리한다. 답변 일부만 도착하면 해당 주장만 갱신한다.

## 먼저 확인할 항목

### OWN-01 — 사내 자료의 공개 가능한 범위

- **왜 필요한가:** 지금 요약에 들어 있는 수치가 모두 기존 공개 자료에 있었던 것은 아니다. 사용자가 보안에 유의하라고 명시했다.
- **정확히 확인할 것:** 에셋 검수 완료 16,052개·중복 47행·건너뛰기 187개, 인력 분석의 역검증 88일·23/24일, 자동화 README의 월 10시간 주장, 영상의 수정 실패/후속 변경 사례를 공개 포트폴리오에서 설명해도 되는가? 프로젝트명·서비스/고객명·화면·브랜드 없이 익명으로 설명할 범위와 수치를 구분해 알려줄 것.
- **답변 전 처리:** 이 문서와 근거 요약은 작업 초안이다. 새 사내 수치를 공개 본문으로 자동 이동하지 않고, 회사명·고객명·실화면도 새로 추가하지 않는다. 기존 공개 수준의 일반적인 업무·판단을 중심으로 문장을 정리한다.
- **상태:** 미답변. 실제 비밀값·식별정보·원본 파일은 요청하지 않는다.

### OWN-02 — 사내 6사례에서 직접 맡은 일

- **왜 필요한가:** 저장소에 구현이 있다는 사실과 사용자가 직접 한 일은 다르다.

- **상태:** 일부 답변.

- **2026-10-01 사용자 답변:** NLP 자동제작 부분 전체(자연어 카테고리 선택→이미지 배분)의 직접 기여 확인. 인력 분석의 실제 채용 반영 및 자동화의 사용자·효과도 설명됨.
- **반영과 근거 수준:** NLP 기여 범위는 반영 완료. 에셋은 개발 담당과 검수자 피드백에 따른 기능 추가를 후속 답변으로 확인했다. 콘텐츠 개인 검수는 제작자 영역이다. 영상·자동화·인력·RAG의 업무 단계별 기여는 추가 답변 필요.

### STF-02 — 600만 원 절감의 실제 산식과 적용

- **확인된 것:** 2월 보고서의 피크 산정·보수안·역검증. 여름 사후 실적은 그 PDF에 없다.

- **필요한 근거:** 공개 가능한 산식 또는 집계 수준의 전후 비교. 개인 급여·명단·계약서 원문은 불필요.

- **상태:** 확인 완료.

- **2026-10-01 사용자 답변:** 전년 대비 실제 인력 3명 감소로 600만 원 절감. 분석 결과가 실제 인원 감소로 이어졌음.
- **반영과 근거 수준:** 공개 소개에 전년 대비 3명·600만 원 실제 절감 반영. 근거 수준은 사용자 설명. 상세 급여·근무 기간별 산식은 회수하지 않았음. 적용 후 운영 결과는 STF-03의 후속 답변을 연결.

### STF-03 — 비용 절감 후 서비스 수준과 Q90 선택 이유

- **정확히 확인할 것:** 변경안 적용 후 응답률/포기호/잔업/증원은 어떻게 됐나? 기간과 비교 기준은 무엇인가? 수치를 모으지 않았다면 당시 관찰은 무엇인가? Q90과 보수안을 선택할 때 감수한 비용·미응답 위험과 현장 의견은 무엇이었나?

### AST-03 — 검수 UX·모델 전환·로딩 개선의 판단과 결과

- **정확히 확인할 것:** 검수자가 가장 힘들어하던 단계와 그 피드백으로 바꾼 화면 기능은 무엇인가? ‘5분 이상’이 걸린 것은 초기 화면·전체 목록·이미지 중 무엇이며 개선 후 실측이 있는가? Flux에서 클라우드 생성으로 바꾼 당시 선택지는 무엇이고 품질·시간·비용 중 어떤 기준이 결정적이었나? 투입 시간/검수 처리량/실제 청구액 기록이 있는가?
- **답변 전 처리:** 구현된 검수 기능은 설명하되 정량 효율과 실제 비용 절감은 단정하지 않는다. 1,000건 예상 시간을 완료 기록으로 쓰지 않는다.
- **상태:** 일부 답변.

- **2026-10-01 사용자 답변:** 매년 발생하던 라이선스 비용을 AI 제작 비용으로 대체했고, 대상 전체 제작 비용은 연간 라이선스 비용의 약 40%. 사용자는 이를 ROI 약 0.4년으로 표현했다. 구체적인 금액은 공개할 수 없다고 명시했다.
- **2026-10-01 후속 답변:** 비용은 생성 API만 포함. 인건비와 구체 금액은 공개 불가하며 재질문하지 않는다. 기존 라이선스 실제 종료 완료. 대체 후 지속 비용은 없으며 이후 소량 콘텐츠 생성 비용은 사용자가 무시 가능한 수준이라고 설명함.
- **반영:** 연간 라이선스 비용의 약 40%인 생성 API 비용으로 전체 대체, 실제 서비스 반영·라이선스 종료를 공개. 약 0.4년은 API 비용 기준 회수 기간으로 쓰며 인건비 포함 총사업비 ROI로 확대하지 않음. 반복 라이선스 제거와 플랫폼 전체 운영비 0을 구별.
- **2026-10-01 개발·피드백 답변:** 콘텐츠 제작자가 개인 검수했고 사용자는 개발 담당. 피드백으로 대량 재생성, 태그 등 정보 수정 후 실제 DB 직접 반영, 카테고리별 부족 현황 페이지를 추가했다.

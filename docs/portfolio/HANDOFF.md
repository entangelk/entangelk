## 현재 완료한 내용

- README·PROJECTS 두 언어, 홈·실무·케이스 상세를 사용자 문제→선택→작업 흐름→구현/적용→검증 범위로 정리했다.
- README·PROJECTS는 실제 적용 성과인 인력 분석·에셋·NLP·자동화를 앞에 배치했다. Writer는 직접 사용·개발 중 제품, 영상은 개발 중 B2B 광고 제품, RAG·Memory는 기술 기반으로 구분했다.
- Assessment는 기존 합성 예제 검증 외 추가 진행이 없는 보조 PoC로 내렸다. 홈의 Assessment 슬롯은 월간보고 자동화로 바꿨고 상세 기록은 보존했다.
- 케이스 상세 순서는 Writer→Memory→Harness IR→Assessment다. 기존 앵커·이미지·기술 근거는 유지했다.
- 기술 기록·테스트 수를 사용자 성과로 쓰는 문구와 NLP의 다른 작업량 속도 비교를 바로잡았다.
- 내부 확인 대기 메모를 공개 소개에서 제거했다. 자료를 확보하지 못한 것을 ‘미측정/실사용 없음’으로 단정하지 않는다.
- 회사 원본 코드·로그·PDF·이미지·인증값·사내 주소·개인별 자료는 추가하지 않았다. 작업 문서의 세부 집계와 공개 소개는 용도가 다르며 세부 집계를 대표 본문으로 자동 이동하지 않는다.

## 사용자가 이어갈 일과 작업 순서

구체적인 체크박스·프로젝트별 산출물은 [NEXT_ACTIONS](https://github.com/entangelk/entangelk/blob/main/docs/portfolio/NEXT_ACTIONS.md)에 둔다.

1. **WR-01:** Writer 프로젝트 README를 정리할 때 직접 사용→화면 불편→개선 사례를 Git 이력으로 확인한다. 로컬 이력에서 2026-09-30 `97e110c`·`600803f`와 9월 2일 검토 UX 보강 기록은 읽었다. 원본 프로젝트 파일은 수정하지 않았다.
2. **CO-01~05:** 영상·에셋·NLP·자동화·RAG 두 저장소의 README를 회사에서 갱신한다. 집에서는 근거 요약으로 문안 작성이 가능하다. 공개 GitHub 주소가 없는 사내 저장소의 링크를 만들지 않는다.
3. **PDF-01:** [경력기술서 저장소](https://github.com/entangelk/job_activate)의 두 HTML 원본과 인쇄 지침을 확인했다. `경력기술서.html`과 `AI_Writer_포트폴리오.html`을 수정해 Chrome으로 PDF를 재생성한다. 원본 저장소는 읽기만 했고 사용자 미추적 파일을 보존했다.
4. **CV-01:** 검증한 PDF를 포트폴리오에 반영하고 포트폴리오·경력기술서의 기여도·상태·성과·링크를 대조한다. 경력기술서 저장소의 후속 업데이트는 사용자가 이미 요청했다.
5. **선택 작업:** Assessment·Memory·연구 README는 체크리스트의 권고를 보고 필요한 문구만 수정한다. 추가 인터뷰·파일럿·벤치마크를 제출의 의무 조건으로 만들지 않는다.

OWN-01(아직 대표 본문에 사용하지 않은 사내 세부 집계의 공개 범위)·OPS-03(과거 특정 CMS/API 재사용 흐름)은 선택적 보강이다. 전체 작업의 선행 조건이 아니다. 답변이 충분한 상태·기여도·성과를 다시 확인받지 않는다. 인건비·구체 금액·사내 레퍼런스 구성·검수자의 개인 기준을 재질문하지 않는다.

## PDF의 현재 상태

기존 `docs/portfolio`의 Writer PDF는 14쪽, 경력기술서 PDF는 18쪽이다. 아직 이번 개편과 동기화하지 않았다. Writer PDF에는 이전의 일관성 단정과 검증 기록 중심 구성이, 경력기술서 PDF에는 월 10시간 절감 등의 예전 문구가 남아 있다.

2026-10-01 원본 저장소의 HTML 두 개와 HANDOFF를 읽어 생성 경로를 확인했다. Tabloid 가로 17×11인치의 Chrome PDF 인쇄 지침이 있다. 원본과 정확한 GitHub 연결은 NEXT_ACTIONS의 PDF-01 표를 따른다. 현재 웹을 단순 인쇄한 파일로 경력기술서의 편집 원본을 대체하지 않는다.

## 커밋·push와 검증

사용자가 2026-10-01 필요한 만큼 커밋하면서 진행하도록 승인했고, 마지막 요청에서 **핸드오프·사용자 체크리스트 갱신 후 커밋·push**를 명시했다. 이전 ‘push하지 않는다’는 세션 지침은 이번 요청으로 대체됐다.

이번 push 대상은 포트폴리오 저장소의 **`origin/main`**이다. 원격은 [entangelk/entangelk](https://github.com/entangelk/entangelk). 다른 프로젝트와 경력기술서 저장소는 수정·push하지 않는다. 원격 동기화의 실제 결과는 작업 종료 보고와 `git status -sb`, `git ls-remote origin refs/heads/main`으로 확인한다. 이 문서 작성 시점에는 최종 문서 커밋·push를 이어서 수행한다.

- 현재 본문의 기여도 정정까지는 `8299427`에 기록돼 있다. 후속 문서 정리는 이 파일과 NEXT_ACTIONS를 포함한 별도 커밋으로 남긴다.
- 로컬 링크·이미지 경로·앵커·중복 ID·한영 문장·Markdown 참조·`git diff --check`를 검사했다.
- 대표 사례 재배치 시 Chromium 153으로 3페이지 × 한영 × 데스크톱 1440px/모바일 390px의 12개 조합을 확인했다. 언어 전환·가로 넘침·이미지·상세 펼침·인쇄 전 열기/복원을 확인했다.
- 그 후 비율·문장 정정은 정적 검사로 확인했다. 이번 작업은 인계 문서 변경이며 본문·CSS·JS를 다시 수정하지 않는다.
- 기존 PDF 재출력·배포 사이트 확인·회사 서비스 재실행·외부 사용자 실험은 수행하지 않았다. 임시 검사 도구와 스크린샷은 `/tmp`에만 있다.

새 사실이나 산출물이 생기면 질문/근거 기록→본문 두 언어·웹→체크리스트→핸드오프를 함께 갱신한다. 내부 질문을 README·PROJECTS·웹 소개에 노출하지 않는다.

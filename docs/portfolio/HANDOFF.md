## 목표와 이어가기 원칙

AI Product Builder 관점에서 **사용자 문제→제품 판단→업무/UX→구현→검증→다음 결정**을 보여주는 포트폴리오로 개편한다. 기술 깊이와 실패 기록은 보존하되 기술 구조·테스트 수를 대표 성과처럼 앞세우지 않는다.

사용자는 집에서 회사 저장소에 접근할 수 없다. 회사 자료를 다시 열지 않고 아래 근거 요약으로 문구 개편을 진행한다. 부족한 사실은 사용자 확인 항목으로 남기고, 답변이 없는 주장만 미확인으로 유지한다. 전체 작업을 확인 대기로 멈추지 않는다.

## 검증과 핸드오프 갱신

2026-10-01 변경 범위 검증을 완료했다.

- 정적 검사: 세 웹 페이지의 로컬 링크·이미지 경로·앵커·중복 ID, 한영 문장 쌍, Markdown 파일 참조·코드 펜스, `git diff --check` 통과.
- Chromium 153: 홈·실무·케이스 페이지 × 한국어/영어 × 데스크톱 1440px/모바일 390px의 **12개 조합** 통과. 가로 넘침·초기 표시 이미지 로드·비활성 언어 숨김·로컬 링크의 언어 유지·언어 전환·상세 펼침/접힘을 확인했다. 모바일 홈과 데스크톱 실무 화면도 직접 확인했다.
- 케이스 페이지의 인쇄 전 상세 열기와 인쇄 후 원래 상태 복원을 확인했다. 실제 PDF 내보내기의 페이지 분할·그림 배치와 기존 PDF의 갱신은 별도 미완료다.
- 외부 링크 응답·배포 사이트·회사 서비스 실행·제품 지표를 새로 검증하지 않았다. 로컬 본문 검증은 제품 효과 검증과 다르다.

임시 검사 스크립트·브라우저 프로필·스크린샷은 `/tmp`에만 두고 커밋하지 않았다. 검사 스크립트는 재개 세션의 영구 의존성이 아니다. 같은 범위의 검증을 완료했으며 추가 본문 변경이 없으면 전체 검사를 반복할 필요는 없다.

문서 변경 시 영향받는 참조·수치·표를 확인하고 `git diff --check`를 실행한다. untracked 문서는 이 명령만으로 검사되지 않으므로 파일 자체도 확인한다. 본문 구현 후에는 변경된 사용자 흐름에 맞는 브라우저 확인을 추가한다. 작업 상태·다음 단계·미확인이 바뀌면 이 문서를 현재 상태로 고쳐 남긴다.

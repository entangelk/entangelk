# 포트폴리오 개편 핸드오프

기준일: 2026-10-01 · 현재 단계: P0 사용자 확인 대기 / P1 README·홈 개편 완료, 상세 개편 대기

## 목표와 이어가기 원칙

AI Product Builder 관점에서 **사용자 문제→제품 판단→업무/UX→구현→검증→다음 결정**을 보여주는 포트폴리오로 개편한다. 기술 깊이와 실패 기록은 보존하되 기술 구조·테스트 수를 대표 성과처럼 앞세우지 않는다.

사용자는 집에서 회사 저장소에 접근할 수 없다. 회사 자료를 다시 열지 않고 아래 근거 요약으로 문구 개편을 진행한다. 부족한 사실은 사용자 확인 항목으로 남기고, 답변이 없는 주장만 미확인으로 유지한다. 전체 작업을 확인 대기로 멈추지 않는다.

## 먼저 읽을 문서

1. [개편 계획과 백로그](portfolio-revision-plan.md): P0~P6, 우선순위, 완료 기준.
2. [사내 근거 요약](company-evidence-snapshot.md): 회사에서 확인한 6사례의 흐름·집계·실패·수치 조건·개편 문장 초안. 현재 공개 본문보다 최신 조건을 포함한다.
3. [사용자 확인 대기 목록](owner-confirmations.md): 정확한 질문, 답변 전 처리, 답변 기록 양식. 지금은 모두 미답변.
4. [증거 수집표](portfolio-evidence-workbook.md): 근거 수준과 다음 실사용 검증 방법.

충돌하면 새로 확인한 근거와 실제 측정 조건을 우선하되, 자료 충돌/미확인을 숨기지 않는다. 사용자 답변은 답변일·근거 수준을 붙여 반영한다. 요구사항 문서만 보고 기능 구현이나 실제 성과를 확정하지 않는다.

## 완료한 작업과 아직 하지 않은 작업

- 공개 README·PROJECTS·웹 HTML을 적대적 검증 글과 대조했다. 핵심은 시스템 검증이 사용자 성과를 가리는 문제이며, 기획 역량의 부재까지 확정하지 않았다.
- 회사 자료를 읽어 영상·에셋·NLP·사내 자동화·인력 분석·RAG의 개편용 요약을 확보했다. 인력 보고서는 8페이지를 직접 판독했고, 에셋은 로컬 파일에서 집계했다.
- 계획·근거표·사용자 질문 목록을 작성했다. 원본 복사 대신 비식별 설명·집계·한계를 남겼다.
- README 두 언어와 홈 소개를 사용자 문제·경험·검증 상태 중심으로 개편했다. 홈의 Memory/Harness 노출을 줄이고 인력 분석·영상·Assessment를 연결했다. NLP 비교 배수는 홈에서 내렸고 에셋 수치를 생성 인덱스로 한정했다.
- PROJECTS와 상세 페이지의 표현·주장 정리는 다음 작업이다. 실사용 실험·인터뷰·운영 DB 조회·서비스/모델 재실행·PDF 업데이트는 수행하지 않았다.
- 계획·근거 문서는 `c5fc4b0`으로 커밋했다. 사용자가 필요한 만큼 커밋하면서 진행하도록 승인했다. 완료한 묶음마다 검증과 핸드오프 갱신 후 커밋한다. push는 수행하지 않는다. 재개할 때 `git status --short`를 확인하고 다른 변경을 보존한다.

## 다음 작업자가 바로 진행할 순서

1. Git 상태와 이 문서들을 확인한다. 사내 저장소 탐색이나 원본 회수를 다시 시작할 필요는 없다.
2. C01~C03의 README·홈 개편은 완료했다. C04의 상세 문구를 정리하고 PROJECTS와 웹의 주장·검증 상태를 맞춘다.
3. 인력 분석의 판단 구조와 에셋의 검수 업무를 앞쪽 배치 후보로 사용한다. 대표 AI 사례 3개를 의무적으로 강하게 포장하지 않는다. 미검증 상태를 함께 표시한다.
4. NLP의 성능 비교 조건을 바로잡고 과장 표현을 낮춘다. 한국어 변경과 같은 묶음에서 영어·웹·Markdown의 상태/수치/주장을 동기화한다.
5. P2/P4: 사내 근거 요약의 문장 초안을 사례별 상세에 적용한다. 새로운 사용자 수·성과 수치는 만들지 않는다. 질문이 필요한 주장만 해당 ID로 남긴다.
6. 답변이 도착하면 확인 목록→근거 요약→증거표→계획 상태→본문 순으로 반영한다. 모든 질문을 한 번에 다시 묻지 않고 관련 묶음만 확인한다.
7. 링크·한영·모바일·접힌 상세·인쇄/PDF 동작을 변경 범위에 맞춰 검토한다. 실사용 실험은 P3에서 별도 진행한다.
8. 포트폴리오 개편 완료 후 P6로 [경력기술서 저장소](https://github.com/entangelk/job_activate)의 관련 문서·산출물을 동기화한다. 이 요청은 이미 계획에 포함돼 있다.

## 파일과 공개 자료 연결

개편 대상은 루트의 `README.md`, `README.ko.md`, `PROJECTS.md`, `PROJECTS.ko.md`와 `docs/index.html`, `docs/experience.html`, `docs/case-studies.html`이다. 사이트는 정적 HTML·CSS·JS이며 이미 기술 상세를 접는 `details.evidence-details` 구조가 있다. 이번 근거 확보만을 이유로 UI를 전면 재개발하지 않는다.

공개 소스는 [프로필 저장소](https://github.com/entangelk/entangelk), 사이트는 [포트폴리오](https://entangelk.github.io/entangelk/)다. 사내 저장소의 공개 GitHub 주소는 미확인이고 링크를 만들지 않았다. 사내 로컬 경로·private remote를 공개 링크로 대체하는 작업도 하지 않는다.

`docs/portfolio`의 Markdown은 공개 저장소에 올라갈 수 있는 초안으로 취급한다. 이 HANDOFF는 Git 제외 대상인 `docs/HANDOFF.md`와 다른 파일이며, 함께 인계할 수 있도록 포트폴리오 폴더에 둔다. 원본 코드·로그·PDF·이미지·인증값·사내 주소·개인별 기록은 추가하지 않는다. PDF 검토용 임시 이미지는 삭제했다.

## 검증과 핸드오프 갱신

문서 검사와 첫 본문 변경의 로컬 링크·이미지·앵커·중복 ID·한영 문장 쌍·Markdown 검사를 통과했다. 브라우저 확인은 다음 묶음에서 진행한다. 외부 링크 접근·서비스 실행 결과를 검증했다고 쓰지 않는다.

문서 변경 시 영향받는 참조·수치·표를 확인하고 `git diff --check`를 실행한다. untracked 문서는 이 명령만으로 검사되지 않으므로 파일 자체도 확인한다. 본문 구현 후에는 변경된 사용자 흐름에 맞는 브라우저 확인을 추가한다. 작업 상태·다음 단계·미확인이 바뀌면 이 문서를 현재 상태로 고쳐 남긴다.
